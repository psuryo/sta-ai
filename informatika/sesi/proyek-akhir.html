Panduan lengkap proyek UAS: 11 topik proyek AI setara tingkat kesulitan, pembagian peran kelompok, format laporan ilmiah, rubrik penilaian, timeline, dan ketentuan integritas akademik.

Proyek 11 kelompok × 4 mahasiswa Bobot UAS 35%

Tujuan

Halaman ini memperkenalkan proyek akhir sebagai penutup mata kuliah. Setelah membaca panduan ini, mahasiswa diharapkan mampu:

  1. Memahami ruang lingkup, bobot penilaian, dan timeline proyek UAS
  2. Membandingkan 11 topik proyek (domain, teknik ML, dataset) dan mempersiapkan preferensi topik kelompok
  3. Membagi peran dalam kelompok (Data Engineer, ML Engineer, App Developer, Research Writer)
  4. Menyusun laporan ilmiah sesuai struktur dan format yang ditetapkan
  5. Memahami kebijakan penggunaan AI dan integritas akademik dalam pengerjaan proyek
📌

Topik per kelompok diumumkan dosen pada Pertemuan 13. Gunakan halaman ini untuk mempelajari semua topik karena tiap kelompok mendapat satu topik, dan sesi tanya jawab individual pada UAS dapat mencakup bagian mana pun dari proyek.

P01 Deteksi Hoaks Berbahasa IndonesiaNatural Language Processing · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi web yang menerima teks berita/artikel dan mengklasifikasikannya sebagai hoaks atau bukan. Dilengkapi visualisasi top-10 kata paling berpengaruh per prediksi (explainability sederhana dengan SHAP).

Stack Teknologi

Python Scikit-learn (TF-IDF + Logistic Regression / SVM) SHAP Streamlit

Dataset

IDHoax dataset (GitHub) + sampel turnbackhoax.id (~3.000 artikel, sudah terlabel)

Scope & Pembatasan
  • Klasifikasi biner: hoaks / bukan hoaks
  • Dua algoritma dibandingkan: SVM vs Logistic Regression
  • Explainability: SHAP values (top-10 kata per prediksi)
  • Evaluasi: accuracy, precision, recall, F1 per kelas
Kontribusi Ilmiah

Perbandingan SVM vs Logistic Regression untuk deteksi hoaks Bahasa Indonesia; analisis fitur linguistik paling prediktif; evaluasi pada dua subdomain berita (kesehatan vs politik).

Mengapa ★★★☆☆?

Dataset tersedia bersih tanpa scraping kompleks. Dua algoritma sudah matang dan terdokumentasi. Explainability cukup dengan SHAP tanpa pipeline tambahan.

P02 Sistem Rekomendasi Film Content-BasedRecommender System · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi rekomendasi film berdasarkan kemiripan konten (genre, sutradara, aktor, sinopsis). Pengguna memasukkan judul film favorit dan sistem menampilkan 10 film paling mirip beserta alasannya.

Stack Teknologi

Python Scikit-learn (TF-IDF, Cosine Similarity) Pandas Streamlit TMDb API (poster)

Dataset

MovieLens Latest Small (100k ratings) + metadata dari TMDb API

Scope & Pembatasan
  • Content-based filtering murni (tanpa collaborative filtering)
  • Fitur: genre, sinopsis (TF-IDF), metadata dasar
  • Evaluasi: precision@k dan user study sederhana (5 responden)
  • Tidak perlu menangani cold-start problem
Kontribusi Ilmiah

Analisis pengaruh bobot fitur (genre saja vs genre+sinopsis vs semua fitur) terhadap relevansi rekomendasi; evaluasi kombinasi metrik otomatis dan penilaian pengguna.

Mengapa ★★★☆☆?

MovieLens sangat bersih dan kecil. Cosine similarity tidak memerlukan training kompleks. Precision@k mudah diimplementasikan.

P03 Deteksi Penyakit Daun Padi dari FotoComputer Vision · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi mobile-friendly yang menerima foto daun padi dan mendiagnosis penyakit (blast, brown spot, bacterial blight, leaf smut) dengan CNN transfer learning. Cocok diakses dari smartphone petani di lapangan.

Stack Teknologi

Python TensorFlow/Keras Transfer Learning (MobileNetV2) Streamlit (mobile-responsive)

Dataset

Rice Leaf Disease dataset dari Kaggle (~3.000 foto, 4 kelas, sudah bersih dan terlabel)

Scope & Pembatasan
  • Klasifikasi 4 kelas penyakit daun padi
  • Satu arsitektur: MobileNetV2 pretrained ImageNet, fine-tuned
  • Augmentasi standar: flip, rotate, zoom
  • Evaluasi: accuracy, F1 per kelas, confusion matrix
Kontribusi Ilmiah

Evaluasi MobileNetV2 untuk deteksi penyakit padi; analisis dampak augmentasi terhadap performa; diskusi kelayakan deployment di perangkat mobile dengan resource terbatas.

Mengapa ★★★☆☆?

Dataset bersih di Kaggle. Transfer learning MobileNetV2 sangat terdokumentasi. Satu arsitektur yang dievaluasi mendalam lebih baik daripada banyak arsitektur yang dangkal.

P04 Chatbot Tanya Jawab Akademik Berbasis RAGGenerative AI · RAG · ★★★☆☆ ▾
Deskripsi Aplikasi

Chatbot yang menjawab pertanyaan mahasiswa tentang peraturan akademik, prosedur administrasi, dan kurikulum berdasarkan dokumen PDF resmi institusi. RAG menjaga jawaban tetap berakar pada dokumen, bukan halusinasi LLM.

Stack Teknologi

Python LangChain ChromaDB OpenAI / Claude API Streamlit

Dataset

Dokumen akademik institusi (PDF): buku pedoman, peraturan akademik, FAQ (5–10 dokumen)

Scope & Pembatasan
  • Pipeline RAG standar: PDF loader → text splitter → embedding → ChromaDB → retrieval → generation
  • Evaluasi: 30 pertanyaan uji manual (relevansi & kebenaran jawaban)
  • Tidak perlu training model — konfigurasi pipeline dan evaluasi kualitatif
Kontribusi Ilmiah

Evaluasi dampak ukuran chunk (500 vs 1.000 vs 1.500 karakter); perbandingan RAG vs LLM murni pada 30 pertanyaan uji; analisis tipe pertanyaan tersulit.

Mengapa ★★★☆☆?

Pipeline LangChain + ChromaDB sudah sangat terdokumentasi. Dataset mudah didapat. Tidak perlu training model.

P05 Prediksi Harga Properti di SurabayaTabular Machine Learning · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi yang memprediksi harga jual properti di Surabaya berdasarkan kecamatan, luas tanah, luas bangunan, jumlah kamar tidur, jumlah kamar mandi, dan garasi. Dilengkapi peta interaktif distribusi harga per kecamatan.

Stack Teknologi

Python Scikit-learn (Random Forest, XGBoost) Pandas Plotly Streamlit

Dataset

Scraping listing satu platform (99.co atau Rumah123) untuk Surabaya, target 2.000–3.000 listing; scraping dilakukan sekali dan data disimpan statis

Scope & Pembatasan
  • Dua model dibandingkan: Random Forest vs XGBoost
  • 6 fitur numerik/kategorikal
  • Evaluasi: RMSE, MAE, R², feature importance
  • Preprocessing standar: encoding kecamatan, handling outlier harga
Kontribusi Ilmiah

Perbandingan Random Forest vs XGBoost untuk harga properti Surabaya; analisis feature importance; pemetaan distribusi harga per kecamatan sebagai insight bisnis.

Mengapa ★★★☆☆?

Scraping halaman statis relatif mudah. Dua algoritma matang. Fitur sedikit dan maknanya jelas. Evaluasi regresi standar.

P06 Analisis Sentimen Ulasan Produk Lokal E-commerceNatural Language Processing · ★★★☆☆ ▾
Deskripsi Aplikasi

Sistem yang mengklasifikasikan ulasan produk UMKM ke sentimen positif, netral, atau negatif. Dashboard per produk: distribusi sentimen, tren per bulan, dan word cloud.

Stack Teknologi

Python Scikit-learn (TF-IDF + Naive Bayes / SVM) PySastrawi WordCloud Plotly Streamlit

Dataset

Scraping ulasan satu kategori produk di Tokopedia atau Shopee (~3.000 ulasan); pelabelan manual 1.000 ulasan oleh anggota tim

Scope & Pembatasan
  • Klasifikasi 3 kelas: positif / netral / negatif
  • Dua model dibandingkan: Naive Bayes vs SVM
  • Preprocessing: tokenisasi, stopword removal, stemming (PySastrawi)
  • Dashboard: distribusi sentimen, tren, word cloud per kelas
Kontribusi Ilmiah

Evaluasi Naive Bayes vs SVM untuk ulasan Bahasa Indonesia non-formal; pengaruh stemming terhadap akurasi; kata paling diskriminatif per kelas sentimen.

Mengapa ★★★☆☆?

Scraping ulasan relatif mudah. Dua algoritma cocok untuk teks pendek. PySastrawi tersedia. Pelabelan 1.000 data realistis (250 per orang).

P07 Klasifikasi Sampah dari GambarComputer Vision · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi yang mengklasifikasikan foto sampah ke 6 kategori (organik, plastik, kertas, logam, kaca, residu) dengan CNN transfer learning, dapat diakses dari browser di berbagai perangkat.

Stack Teknologi

Python TensorFlow/Keras Transfer Learning (EfficientNetB0) Streamlit

Dataset

TrashNet (2.527 foto, 6 kelas, GitHub) + minimal 200 foto tambahan per kelas yang diambil sendiri untuk konteks lokal Indonesia

Scope & Pembatasan
  • Klasifikasi 6 kelas sampah
  • Satu arsitektur: EfficientNetB0 pretrained ImageNet, fine-tuned
  • Augmentasi standar
  • Evaluasi: accuracy, F1 per kelas, confusion matrix; diskusi kelas yang paling sering salah
Kontribusi Ilmiah

Evaluasi EfficientNetB0 dengan konteks lokal Indonesia; dampak penambahan data lokal terhadap baseline TrashNet; pasangan kelas yang paling sering tertukar.

Mengapa ★★★☆☆?

TrashNet lengkap dan bersih. EfficientNetB0 ringan dan terdokumentasi. 200 foto per kelas realistis (50 per orang per kelas).

P08 Prediksi Performa Akademik MahasiswaTabular Machine Learning · ★★★☆☆ ▾
Deskripsi Aplikasi

Sistem yang memprediksi IPK akhir semester dari data awal semester, dilengkapi visualisasi faktor paling berpengaruh dengan SHAP sehingga dosen pembimbing akademik memahami alasan prediksi.

Stack Teknologi

Python Scikit-learn (Decision Tree, Random Forest) SHAP Pandas Streamlit

UCI Student Performance (649 data) atau Students' Dropout and Academic Success (4.424 data) — publik, tanpa data sensitif internal

  • Evaluasi: RMSE, MAE, R²

  • Antarmuka: input satu mahasiswa → prediksi IPK + penjelasan faktor
Kontribusi Ilmiah

Perbandingan Decision Tree vs Random Forest untuk performa akademik; analisis SHAP untuk faktor paling berpengaruh; diskusi implikasi etis sistem prediksi di pendidikan.

Mengapa ★★★☆☆?

Dataset publik dan bersih. Kedua model mudah diimplementasikan. SHAP untuk keduanya sangat terdokumentasi. Tidak ada isu privasi.

P09 Generator Soal Ujian Otomatis dari Materi PDFGenerative AI · Prompt Engineering · ★★★☆☆ ▾
Deskripsi Aplikasi

Aplikasi yang menerima upload PDF materi kuliah dan menghasilkan soal pilihan ganda beserta kunci jawaban dan penjelasan menggunakan LLM. Dosen mengatur jumlah soal, tingkat kesulitan, dan cakupan halaman.

Stack Teknologi

Python PyPDF2 / pdfplumber OpenAI / Claude API LangChain (text splitting) Streamlit

Dataset

Tanpa dataset training. Evaluasi: 5 dokumen materi dari 5 mata kuliah; 3 evaluator (dosen) menilai dengan rubrik standar

Scope & Pembatasan
  • Tiga strategi prompting dibandingkan: zero-shot, few-shot (3 contoh), chain-of-thought
  • Evaluasi: kebenaran konten, kejelasan bahasa, tingkat kognitif Bloom (C1–C4)
  • Minimal 150 soal dievaluasi (50 per strategi)
Kontribusi Ilmiah

Perbandingan tiga strategi prompting terhadap kualitas soal; evaluasi distribusi tingkat kognitif Bloom pada soal AI-generated vs soal buatan dosen.

Mengapa ★★★☆☆?

Tidak butuh training — hanya integrasi API dan text splitting. Tiga strategi prompting terdokumentasi. Rubrik jelas membatasi kompleksitas.

P10 Deteksi Anomali Transaksi KeuanganUnsupervised Machine Learning · ★★★☆☆ ▾
Deskripsi Aplikasi

Sistem yang menganalisis transaksi keuangan untuk mendeteksi anomali yang berpotensi fraud. Dashboard interaktif menampilkan transaksi mencurigakan, skor anomali, dan fitur penyebabnya.

Stack Teknologi

Python Scikit-learn (Isolation Forest, Local Outlier Factor) Pandas Plotly Streamlit

Dataset

Credit Card Fraud Detection (Kaggle) — 284.807 transaksi, publik, teranonimasi dengan PCA

Scope & Pembatasan
  • Dua algoritma dibandingkan: Isolation Forest vs LOF
  • Evaluasi: precision, recall, F1 untuk kelas fraud
  • Analisis trade-off berbagai threshold
  • Dashboard: scatter plot skor anomali + tabel transaksi mencurigakan
Kontribusi Ilmiah

Perbandingan Isolation Forest vs LOF untuk deteksi fraud; sensitivitas threshold terhadap trade-off precision-recall; tantangan imbalanced class pada anomaly detection.

Mengapa ★★★☆☆?

Dataset bersih dan publik. Dua algoritma unsupervised matang di Scikit-learn. Evaluasi standar tanpa pipeline kompleks.

  • Preprocessing: deteksi & crop wajah dengan Haar Cascade
  • Evaluasi: accuracy, F1 per kelas, confusion matrix
Kontribusi Ilmiah

Evaluasi VGG16 fine-tuned untuk ekspresi wajah; analisis ekspresi yang paling sering tertukar; tantangan FER2013 (kualitas rendah, label noise).

Mengapa ★★★☆☆?

FER2013 bersih di Kaggle. Fine-tuning VGG16 sangat terdokumentasi. Haar Cascade built-in di OpenCV.

4. Panduan Penulisan Per Bab

Gunakan panduan ini sebagai checklist saat menulis. Penilai akan memeriksa konsistensi antar bab: rumusan masalah (Bab 1) → research gap (Bab 2) → evaluasi (Bab 4) → kesimpulan (Bab 5).

Panduan Penulisan

BAB 1 · Pendahuluan (~800 kata)

  • 1.1 Latar Belakang
    Mulai dari konteks masalah yang luas, perkecil ke masalah spesifik. Sertakan data/fakta pendukung urgensi. Akhiri dengan transisi ke solusi AI. Hindari kalimat umum seperti "Di era digital ini...".
  • 1.2 Rumusan Masalah
    2–3 pertanyaan penelitian yang spesifik dan terukur. Contoh: "Algoritma mana antara Random Forest dan XGBoost yang memberikan RMSE lebih rendah dalam prediksi harga properti di Surabaya?"
  • 1.3 Tujuan
    Harus 1:1 dengan rumusan masalah. Mulai dengan kata kerja aktif: Membandingkan, Menganalisis, Membangun.
  • 1.4 Batasan
    Nyatakan secara eksplisit apa yang tidak dicakup. Contoh: "Dataset dibatasi pada listing properti di 5 kecamatan Surabaya Pusat periode Jan–Mar 2025."
  • 1.5 Manfaat
    Bedakan manfaat teoritis (kontribusi pada ilmu pengetahuan) dan manfaat praktis (siapa yang menggunakan hasilnya dan bagaimana).
Panduan Penulisan

BAB 2 · Tinjauan Pustaka (~1.200 kata)

  • 2.1 Kajian Terdahulu
    Minimal 8 paper dari 2020–2025 (Google Scholar, Semantic Scholar, IEEE Xplore). Buat tabel: Penulis/Tahun · Metode · Dataset · Hasil Utama · Kelemahan/Gap. Tunjukkan pola dan perkembangan, bukan sekadar merangkum satu per satu.
  • 2.2 Landasan Teori
    Jelaskan algoritma secara konseptual dan matematis secukupnya, fokus pada aspek yang relevan dengan implementasi. Sertakan formula kunci beserta penjelasan variabelnya.
  • 2.3 Posisi Penelitian
    Bagian terpenting Bab 2: apa yang sudah dilakukan peneliti sebelumnya, apa research gap-nya, dan bagaimana penelitian ini mengisinya — terhubung langsung ke rumusan masalah.
Panduan Penulisan

BAB 3 · Metodologi (~1.500 kata)

  • 3.1 Desain Penelitian
    Flowchart alur penelitian dari pengumpulan data hingga evaluasi (draw.io, Lucidchart, atau PowerPoint); setiap kotak diberi penjelasan teks.
  • 3.2 Dataset
    Sumber, cara pengumpulan, jumlah total, distribusi kelas (dengan visualisasi), masalah kualitas data, dan statistik deskriptif (mean, std, min, max).
  • 3.3 Preprocessing
    Langkah berurutan beserta alasannya; tunjukkan statistik sebelum dan sesudah setiap langkah utama.
  • 3.4 Implementasi Model
    Arsitektur, hyperparameter, dan alasan pemilihan. Deep learning: tabel layer-by-layer. ML klasik: hyperparameter awal dan hasil tuning.
  • 3.5 Skema Evaluasi
    Metrik evaluasi dan alasan kesesuaiannya; train-test split dan penggunaan cross-validation.
  • 3.6 Lingkungan Pengembangan
    Tabel spesifikasi: OS, RAM, GPU, versi Python, versi library utama, platform (Colab/lokal) — penting untuk reprodusibilitas.
Panduan Penulisan

BAB 4 · Hasil & Pembahasan (~2.000 kata)

  • 4.1 Hasil Preprocessing
    Statistik deskriptif dan visualisasi distribusi sebelum/sesudah preprocessing; jelaskan keputusan penting.
  • 4.2 Hasil Pelatihan
    Untuk model iteratif: learning curve (training vs validation). Identifikasi overfitting dan cara mengatasinya.
  • 4.3 Evaluasi Model
    Semua metrik dalam tabel rapi. Klasifikasi: confusion matrix + precision/recall/F1 per kelas. Regresi: RMSE, MAE, R² pada train dan test. Dua model dibandingkan dalam satu tabel.
  • 4.4 Tampilan Aplikasi
    Screenshot tiap fitur utama dengan caption deskriptif, user flow 3–5 langkah, contoh input dan output nyata.
  • 4.5 Pembahasan
    Bukan pengulangan hasil, melainkan interpretasi: mengapa model bekerja baik/buruk, apa yang tak terduga, bagaimana dibandingkan paper di Bab 2, apa implikasi praktisnya.
  • 4.6 Keterbatasan
    Jujur tentang kelemahan sistem — keterbatasan yang diakui menunjukkan kematangan ilmiah.
Panduan Penulisan

BAB 5 · Kesimpulan & Saran (~400 kata)

  • 5.1 Kesimpulan
    Jawab setiap rumusan masalah dengan angka konkret.
    ❌ "Model kami memberikan hasil yang baik."
    ✅ "Random Forest menghasilkan RMSE Rp 74.200 pada test set, lebih rendah 15% dibanding baseline Linear Regression."
  • 5.2 Saran
    2–3 saran spesifik dan realistis, bukan sekadar "menambah data".
    ✅ "Mengumpulkan data properti dari 5 kota besar Indonesia untuk model yang lebih general, dengan target RMSE di bawah Rp 50.000."

7. Ketentuan Teknis & Integritas Akademik

Teknis

Ketentuan Aplikasi

  • Aplikasi bisa dijalankan siapa pun — sertakan requirements.txt dan petunjuk instalasi di README.md
  • Seluruh kode di repository GitHub/GitLab; link disertakan dalam laporan
  • Demo live saat presentasi; siapkan backup (video/screenshot) jika koneksi bermasalah
  • Tidak boleh memakai API berbayar yang biayanya ditanggung institusi tanpa persetujuan dosen
Kebijakan AI

Penggunaan Tools AI Diperbolehkan

  • Berlaku untuk ChatGPT, Claude, GitHub Copilot, dll.
  • Kode hasil AI wajib dipahami dan bisa dijelaskan oleh anggota kelompok
  • Laporan tidak boleh sepenuhnya ditulis AI — analisis, interpretasi, dan argumentasi harus pemikiran asli kelompok
  • Cantumkan di Lampiran C: tools AI apa yang dipakai dan untuk bagian mana
Integritas

Integritas Akademik

  • Plagiarisme (kode/teks kelompok lain tanpa atribusi) = nilai 0 untuk seluruh kelompok
  • Laporan melewati pengecekan similarity sebelum dikumpulkan (target < 25%)
  • Dataset harus berlisensi yang memperbolehkan penggunaan akademik — cantumkan sumber dan lisensi dalam laporan
📋 Persiapan Menuju Pertemuan 13

Lakukan hal berikut sebelum Workshop Proyek UAS — Sesi 1.

  1. Baca seluruh 11 deskripsi proyek dan catat minimal 3 topik yang paling menarik bagi kelompokmu.
  2. Bentuk kelompok 4 orang dan diskusikan pembagian peran (Data Engineer, ML Engineer, App Developer, Research Writer).
  3. Eksplorasi dataset dari topik pilihan — pastikan tersedia, berlisensi akademik, dan bisa diunduh.
  4. Siapkan proposal singkat 1 halaman dan rencana kerja untuk presentasi 5 menit di Pertemuan 13.
  5. Buat repository GitHub kelompok dan akun yang dibutuhkan (Kaggle, OpenAI/Anthropic bila topik Generative AI).
