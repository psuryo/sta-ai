2. Skenario A — Prediksi Kegagalan Mesin

⚙️
Predictive Maintenance: Kapan Mesin Akan Gagal?
KASUS NYATA · Predictive Maintenance · Manufaktur

Sebuah pabrik manufaktur mencatat parameter operasional mesin secara real-time: suhu udara, suhu proses, kecepatan putar, torsi, dan keausan pahat. Selama ini teknisi hanya melakukan perawatan terjadwal — bukan berdasarkan kondisi aktual mesin. Biaya downtime akibat kerusakan mendadak 3× lebih mahal dari perawatan preventif. Tugasmu: membangun model yang bisa memprediksi apakah mesin akan gagal berdasarkan parameter sensor, sehingga perawatan bisa dilakukan tepat waktu.

Dataset: predictive_maintenance.csv

Dataset AI4I 2020 Predictive Maintenance — tersedia di Kaggle (Machine Predictive Maintenance Classification oleh shivamb). Berisi 10.000 observasi data sensor mesin yang mensimulasikan kondisi pabrik nyata.

Fitur Input (X)
  • Type (L/M/H)
  • Air temperature [K]
  • Process temperature [K]
  • Rotational speed [rpm]
  • Torque [Nm]
  • Tool wear [min]
Variabel Target (Y)
  • Machine failure
Nilai:
0 — mesin normal
1 — terjadi kegagalan
Statistik Dataset
  • 10.000 observasi
  • 6 fitur input
  • 1 target biner
  • Normal (0): 96,6%
  • Gagal (1): 3,4%
  • Kelas sangat tidak seimbang!

Langkah 3 — Preprocessing

In [5] Preprocessing — Encode & Normalisasi 
# Hapus kolom yang tidak relevan (ID dan sub-tipe kegagalan)
kolom_buang = ['UDI', 'Product ID', 'TWF', 'HDF', 'PWF', 'OSF', 'RNF']
df_bersih = df.drop(columns=[k for k in kolom_buang if k in df.columns])

# Encode kolom kategorik 'Type' (L/M/H) → angka
df_bersih['Type'] = LabelEncoder().fit_transform(df_bersih['Type'])

# Pisahkan fitur (X) dan target (y)
X = df_bersih.drop(columns=['Machine failure'])
y = df_bersih['Machine failure']

# Normalisasi — wajib untuk k-NN agar semua fitur punya skala sama
scaler = StandardScaler()
X_scaled = pd.DataFrame(scaler.fit_transform(X), columns=X.columns)

print("Fitur:", list(X.columns))
print(f"X: {X_scaled.shape} | y: {y.shape}")
print(f"Proporsi gagal dalam y: {y.mean():.1%}")

Langkah 4 — Latih Model & Evaluasi Cross-Validation

In [6] Training — Cross-Validation 10-fold 
# Definisikan dua model
model_dt  = DecisionTreeClassifier(max_depth=5, random_state=42)
model_knn = KNeighborsClassifier(n_neighbors=5)

# Stratified: setiap fold mempertahankan proporsi kelas yang sama
cv = StratifiedKFold(n_splits=10, shuffle=True, random_state=42)

print("=== Hasil 10-fold Stratified Cross-Validation ===\n")
for nama, mdl in [('Decision Tree', model_dt), ('k-NN (k=5)', model_knn)]:
    auc = cross_val_score(mdl, X_scaled, y, cv=cv, scoring='roc_auc')
    rec = cross_val_score(mdl, X_scaled, y, cv=cv, scoring='recall')
    print(f"{nama:20s} | AUC: {auc.mean():.3f} ± {auc.std():.3f}"
          f" | Recall: {rec.mean():.3f} ± {rec.std():.3f}")
Output (contoh)
=== Hasil 10-fold Stratified Cross-Validation ===

Decision Tree | AUC: 0.872 ± 0.023 | Recall: 0.751 ± 0.048
k-NN (k=5) | AUC: 0.841 ± 0.027 | Recall: 0.612 ± 0.061

Langkah 5 — Confusion Matrix & Laporan Klasifikasi

In [7] Evaluasi — Confusion Matrix 
X_train, X_test, y_train, y_test = train_test_split(
    X_scaled, y, test_size=0.2, stratify=y, random_state=42)

fig, axes = plt.subplots(1, 2, figsize=(12, 4))

for ax, (nama, mdl) in zip(axes, [('Decision Tree', model_dt), ('k-NN (k=5)', model_knn)]):

    ConfusionMatrixDisplay.from_predictions(
        y_test, mdl.predict(X_test), ax=ax,
        display_labels=['Normal', 'Gagal'],

    ax.set_title(f'Confusion Matrix — {nama}', fontsize=11)

plt.tight_layout()
plt.show()

# Laporan lengkap Decision Tree

4. Membaca & Menginterpretasi Hasil Evaluasi

Angka yang muncul di output cross-validation hanya bermakna jika kamu memahami apa yang mereka ukur dan dalam konteks apa mereka penting. Berikut empat metrik utama yang akan kamu temui:

Accuracy
(TP + TN) / Total
Cocok ketika kelas seimbang. Menyesatkan untuk kelas tidak seimbang — model yang selalu prediksi "Normal" sudah 96,6% akurat di data kegagalan mesin.
Precision
TP / (TP + FP)
Dari semua yang diprediksi gagal/churn, berapa yang benar? Penting jika biaya false alarm tinggi — mis. menghubungi pelanggan yang tidak akan churn.
Recall
TP / (TP + FN)
Dari semua kejadian nyata, berapa yang terdeteksi? Penting untuk kegagalan mesin — kegagalan yang terlewat = downtime mahal dan tak terduga.
AUC
Area under ROC Curve
Mengukur kemampuan model membedakan dua kelas di semua threshold. AUC = 1,0 sempurna, AUC = 0,5 sama dengan tebakan acak. Metrik terbaik untuk kelas tidak seimbang.

Panduan Interpretasi untuk Konteks Industri

Kasus Industri Prioritaskan Alasan Konsekuensi jika salah prioritas
Prediksi kegagalan mesin Recall Kegagalan yang tidak terdeteksi = downtime mendadak, biaya perbaikan jauh lebih besar Recall rendah → breakdown tak terduga → downtime produksi, kerusakan sekunder
Deteksi cacat produk QC Recall Tidak boleh ada produk cacat yang lolos ke konsumen Recall rendah → produk cacat lolos → komplain, recall produk, reputasi rusak
Prediksi churn pelanggan Recall + Precision Seimbangkan: tangkap sebanyak mungkin churn, tapi jangan ganggu pelanggan loyal terlalu sering Precision rendah → sales menghubungi terlalu banyak non-churner = pemborosan anggaran
Fraud detection pembayaran Precision Memblokir transaksi sah merusak pengalaman pelanggan dan reputasi Precision rendah → terlalu banyak transaksi sah diblokir → pelanggan marah, churn
⚠️

Jangan tertipu akurasi tinggi: Di dataset kegagalan mesin, model yang selalu prediksi "Normal" akan 96,6% akurat — terlihat luar biasa, tapi 100% kegagalan terlewat. Selalu periksa classification_report() dan gunakan AUC atau Recall sebagai metrik utama untuk dataset tidak seimbang.

5. Diskusi Kelas — Decision Tree vs k-NN

Setelah menjalankan kedua model di dua skenario, diskusikan pertanyaan berikut dalam kelompok (5–10 menit):

DecisionTreeClassifier
  • Menghasilkan aturan IF-THEN yang bisa dibaca manusia
  • Mudah dijelaskan ke manajer non-teknis
  • Bisa divisualisasikan dengan plot_tree()
  • Rentan overfitting jika max_depth tidak dibatasi
  • Tidak sensitif terhadap skala fitur
KNeighborsClassifier
  • Tidak ada "model" eksplisit — hanya ingat data training
  • Performa baik pada dataset bersih ukuran menengah
  • Lambat untuk dataset sangat besar
  • Wajib normalisasi — sangat sensitif terhadap skala fitur
  • Sulit dijelaskan mengapa suatu prediksi dibuat
