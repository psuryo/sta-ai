Membangun model prediksi cacat produk dan churn pelanggan menggunakan drag-and-drop di Orange Data Mining — tanpa menulis satu baris kode pun.

Praktik 100 menit CPMK: C2, C3

Tujuan Pembelajaran

Setelah mengikuti pertemuan ini, mahasiswa diharapkan mampu:

  1. Menginstal dan menjalankan antarmuka Orange Data Mining dengan benar
  2. Membangun alur kerja (workflow) klasifikasi dan regresi menggunakan widget drag-and-drop
  3. Memuat dataset industri, melakukan inspeksi awal, dan mengidentifikasi variabel target
  4. Melatih model Decision Tree dan k-NN untuk prediksi cacat produk
  5. Memahami dan menginterpretasi metrik evaluasi model: akurasi, precision, recall, dan AUC
  6. Membandingkan performa dua algoritma berbeda untuk kasus yang sama
🛠️

Persiapan: Pastikan Orange 3.x sudah terinstal di laptop kamu sebelum sesi dimulai (link instalasi ada di Edlink). Bawa laptop dengan minimal 4GB RAM. Dataset yang digunakan hari ini sudah tersedia di folder resources/P03/ di Edlink.

1. Mengenal Orange Data Mining

Orange adalah platform machine learning visual berbasis Python yang dikembangkan oleh Universitas Ljubljana, Slovenia. Filosofinya sederhana: semua langkah analisis data — dari loading, preprocessing, modeling, hingga evaluasi — dilakukan dengan menyambungkan widget secara visual di kanvas.

💡

Mengapa Orange untuk TI? Sebagai insinyur industri, tugas kamu bukan menulis kode ML dari nol — melainkan memahami masalah, memilih metode yang tepat, dan menginterpretasi hasilnya. Orange memungkinkan kamu melakukan semua ini tanpa barrier pemrograman.

2. Skenario A — Klasifikasi Cacat Produk

🔍
Prediksi Cacat Produk di Lini Produksi
KASUS NYATA · Quality Control · Manufaktur FMCG

Sebuah pabrik FMCG (Fast-Moving Consumer Goods) di Surabaya mengalami tingkat reject produk 4,2% — jauh di atas target 1,5%. Inspektur QC sudah kewalahan memeriksa 15.000 unit per hari secara manual. Manajer produksi memintamu membangun model yang bisa memprediksi apakah sebuah unit akan cacat berdasarkan parameter proses produksi yang tercatat di sistem MES.

Dataset: produk_cacat.csv

Dataset berisi 2.400 observasi dari data historis produksi selama 6 bulan terakhir.

Fitur Input (X)
  • suhu_mesin
  • tekanan_cetakan
  • kecepatan_ban_berjalan
  • kelembaban_ruangan
  • umur_cetakan_hari
  • shift (pagi/siang/malam)
  • operator_id
Variabel Target (Y)
  • status_produk
Nilai:
OK — tidak cacat
CACAT — perlu dibuang/rework
Statistik Dataset
  • 2.400 baris observasi
  • 7 fitur input
  • 1 target biner
  • Kelas OK: 78,4%
  • Kelas CACAT: 21,6%
  • Nilai kosong: ~3%

Langkah Praktik — Bangun Workflow di Orange

  1. Load data: Buka Orange → seret widget File ke kanvas → klik dua kali → pilih file produk_cacat.csv. Periksa di pojok kanan bawah widget bahwa Orange berhasil membaca 2.400 baris dan 8 kolom.
  2. Inspeksi awal: Sambungkan File → Data Table. Lihat apakah kolom status_produk bertipe "categorical" (bukan numerik). Jika belum, klik kanan kolom tersebut → Set as Target.
  3. Distribusi fitur: Sambungkan File → Distributions. Pilih fitur suhu_mesin dan shift bergantian. Perhatikan apakah ada perbedaan distribusi antara produk OK dan CACAT.
  4. Preprocessing: Sambungkan File → Preprocess. Aktifkan: Impute Missing Values (pilih "Average/Most frequent"), Normalize Features. Ini penting karena k-NN sensitif terhadap skala fitur.
  5. Masukkan dua model: Dari panel kiri kategori "Model", seret Decision Tree dan kNN ke kanvas. Sambungkan keduanya ke output Preprocess.
  6. Test dan evaluasi: Seret widget Test and Score → sambungkan output Preprocess sebagai Data, dan kedua model sebagai Learner. Atur metode ke Cross Validation, k=10 folds. Klik Run.
  7. Lihat Confusion Matrix: Sambungkan Test and Score → Confusion Matrix. Pilih model yang ditampilkan dan amati di mana model salah mengklasifikasi.
  8. ROC Curve: Sambungkan Test and Score → ROC Analysis. Bandingkan kurva AUC Decision Tree vs k-NN pada kelas CACAT.
🎯

Fokus pada kelas CACAT: Dalam konteks QC, biaya false negative (produk cacat lolos = sampai ke konsumen) jauh lebih mahal dari false positive (produk bagus dibuang = kerugian material). Artinya, kita lebih mementingkan Recall untuk kelas CACAT daripada akurasi keseluruhan.

3. Skenario B — Prediksi Churn Pelanggan

👥
Prediksi Pelanggan yang Akan Berhenti Berlangganan
KASUS NYATA · Customer Retention · Industri Distribusi

Perusahaan distributor spare part industri di Jawa Timur kehilangan 12% pelanggan korporat per tahun. Biaya akuisisi pelanggan baru 5× lebih mahal daripada mempertahankan pelanggan lama. Tim sales memintamu membangun model yang bisa mengidentifikasi pelanggan berisiko tinggi churn — agar tim bisa melakukan intervensi proaktif sebelum mereka pergi.

Dataset: pelanggan_distribusi.csv

Fitur Input (X)
  • total_pembelian_6bln
  • frekuensi_order
  • rata_nilai_order
  • hari_sejak_terakhir_order
  • jumlah_keluhan
  • tenure_bulan
  • tipe_kontrak
Variabel Target (Y)
  • churn
Nilai:
0 — masih aktif
1 — sudah churn
Statistik Dataset
  • 1.800 pelanggan
  • 7 fitur input
  • 1 target biner
  • Aktif (0): 88,1%
  • Churn (1): 11,9%
  • Nilai kosong: <1%

Langkah Tambahan — Interpretasi Decision Tree

  1. Ulangi alur workflow Skenario A dengan dataset pelanggan_distribusi.csv dan target kolom churn.
  2. Setelah melatih model, sambungkan Decision Tree → Decision Tree Viewer. Visualisasi pohon keputusan akan muncul.
  3. Identifikasi root node — fitur apa yang paling pertama digunakan untuk memisahkan data? Ini adalah prediktor terkuat churn.
  4. Telusuri path menuju node "Churn = 1". Aturan apa yang terbentuk? Contoh: "Jika hari_sejak_terakhir_order > 60 AND jumlah_keluhan > 2, maka kemungkinan churn 87%"
  5. Catat 3 aturan IF-THEN terpenting yang dihasilkan pohon. Aturan-aturan ini langsung bisa dikomunikasikan ke tim sales sebagai early warning indicators.
💼

Nilai bisnis nyata: Aturan yang dihasilkan Decision Tree bisa langsung digunakan sebagai trigger otomatis di sistem CRM — misalnya: kirimkan alert ke sales manager ketika pelanggan memenuhi kondisi risiko tinggi, tanpa perlu memahami matematika di balik model.

4. Membaca & Menginterpretasi Hasil Evaluasi

Angka yang dihasilkan widget Test and Score hanya bermakna jika kamu memahami apa yang mereka ukur dan dalam konteks apa mereka penting. Berikut empat metrik utama yang akan kamu temui:

Accuracy
(TP + TN) / Total
Cocok ketika kelas seimbang. Menyesatkan jika kelas sangat tidak seimbang (misal: 95% OK, 5% cacat — model yang selalu prediksi OK sudah 95% akurat).
Precision
TP / (TP + FP)
Dari semua yang diprediksi cacat, berapa yang benar-benar cacat? Penting jika biaya false alarm tinggi (membuang produk bagus).
Recall
TP / (TP + FN)
Dari semua cacat nyata, berapa yang berhasil terdeteksi? Penting jika biaya missed detection tinggi (cacat lolos ke konsumen).
AUC
Area under ROC Curve
Mengukur kemampuan model membedakan dua kelas di semua threshold. AUC = 1,0 sempurna, AUC = 0,5 sama dengan tebak acak. Metrik terbaik untuk kelas tidak seimbang.

Panduan Interpretasi untuk Konteks Industri

Kasus Industri Prioritaskan Alasan Konsekuensi jika salah prioritas
Deteksi cacat produk QC Recall Tidak boleh ada produk cacat yang lolos ke konsumen Recall rendah → recall = produk cacat lolos → komplain pelanggan, recall produk mahal
Prediksi churn pelanggan Recall + Precision Seimbangkan: tangkap sebanyak mungkin churn, tapi jangan ganggu pelanggan loyal terlalu sering Precision rendah → sales menghubungi terlalu banyak pelanggan yang tidak akan churn = pemborosan
Predictive maintenance mesin Recall Kerusakan mesin yang tidak terdeteksi jauh lebih mahal dari penggantian komponen yang belum rusak Recall rendah → breakdown tak terduga → downtime produksi, kerusakan sekunder
Fraud detection pembayaran Precision Memblokir transaksi sah (false positive) merusak pengalaman pelanggan dan reputasi Precision rendah → terlalu banyak transaksi sah diblokir → pelanggan marah, churn
⚠️

Jangan tertipu akurasi tinggi: Dataset cacat produk kita 78% OK dan 22% CACAT. Model yang selalu memprediksi "OK" akan mendapat akurasi 78% — terlihat bagus, tapi sama sekali tidak berguna karena 100% cacat lolos. Selalu periksa confusion matrix untuk memahami di mana model gagal.

5. Diskusi Kelas — Decision Tree vs k-NN

Setelah menjalankan kedua model di dua skenario, diskusikan pertanyaan berikut dalam kelompok (5–10 menit):

Decision Tree
  • Menghasilkan aturan yang bisa dibaca manusia
  • Mudah dijelaskan ke manajer non-teknis
  • Cepat saat prediksi
  • Rentan overfitting jika pohon terlalu dalam
  • Tidak butuh normalisasi fitur
k-Nearest Neighbors
  • Tidak ada "model" eksplisit — hanya ingat data training
  • Performa baik pada dataset kecil-menengah
  • Lambat untuk dataset sangat besar
  • Sangat sensitif terhadap skala fitur (harus dinormalisasi)
  • Sulit dijelaskan mengapa suatu prediksi dibuat

Pertanyaan diskusi: Dari dua skenario yang kamu coba (cacat produk & churn pelanggan), model mana yang lebih baik? Pertimbangkan tidak hanya metrik AUC, tapi juga: siapa yang akan menggunakan hasil prediksi ini? Apakah mereka perlu memahami mengapa model membuat keputusan tertentu?

Ringkasan Pertemuan Ini

  • Orange Data Mining memungkinkan membangun model ML lengkap — dari load data hingga evaluasi — tanpa satu baris kode pun
  • Alur standar: File → Preprocess → Model (Decision Tree / kNN) → Test & Score → Confusion Matrix → ROC Analysis
  • Decision Tree menghasilkan aturan IF-THEN yang bisa langsung diterjemahkan menjadi prosedur operasional
  • Pemilihan metrik evaluasi bergantung pada konteks bisnis — Recall lebih penting dari Precision untuk kasus QC dan predictive maintenance
  • Kelas tidak seimbang (imbalanced class) adalah tantangan umum di data industri — akurasi bisa menyesatkan, AUC lebih andal
  • Setiap prediksi model harus diinterpretasi dalam konteks biaya bisnis: biaya false positive vs false negative berbeda tiap kasus
