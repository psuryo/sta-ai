PERTEMUAN 04 · PRAKTIK

Data Industri:
Pembersihan &
Visualisasi

Mengelola data operasional berkualitas buruk — pembersihan tanpa coding — dan membangun dashboard visual dengan Power BI / Looker Studio untuk mendukung pengambilan keputusan berbasis data.

Praktik 100 menit CPMK: C3, C4

Tujuan Pembelajaran

Setelah mengikuti pertemuan ini, mahasiswa diharapkan mampu:

  1. Mengidentifikasi berbagai jenis masalah kualitas data dalam dataset operasional industri nyata
  2. Menerapkan teknik data cleaning tanpa coding: hapus duplikasi, imputasi nilai kosong, perbaiki format, tangani outlier
  3. Melakukan Exploratory Data Analysis (EDA) visual menggunakan Power BI atau Looker Studio
  4. Membangun dashboard sederhana yang menjawab pertanyaan operasional bisnis tertentu
  5. Membedakan kapan suatu pola dalam data layak dilaporkan kepada manajemen vs memerlukan investigasi lebih lanjut
⚠️

Prinsip "Garbage In, Garbage Out": Model AI yang dibangun di P-03 hanya akan sebaik data yang dimasukkandi dalamnya. Tidak ada algoritma canggih yang bisa mengompensasi data yang kotor, tidak konsisten, atau tidak representatif. Pertemuan ini adalah fondasi yang menentukan kualitas semua analisis selanjutnya.

1. Masalah Kualitas Data di Industri

Data operasional industri — yang berasal dari MES, ERP, sensor IoT, form manual, atau ekspor spreadsheet — hampir selalu datang dalam kondisi tidak sempurna. Memahami jenis-jenis masalahnya adalah langkah pertama sebelum bisa membersihkannya.

🕳️
Missing Values (Nilai Kosong)
Sensor gagal mencatat, operator melewatkan pengisian form, kolom opsional tidak diisi, data hilang saat migrasi sistem. Bisa muncul sebagai sel kosong, "N/A", "-", "0" yang sebenarnya berarti tidak ada data, atau spasi.
→ Strategi: isi dengan rata-rata / median / modus, atau hapus baris
👯
Duplikasi Data
Data yang sama tercatat dua kali akibat double-entry manual, sinkronisasi sistem yang gagal di tengah jalan, atau merge dataset yang tidak bersih. Menggelembungkan jumlah sampel dan distorsi statistik.
→ Strategi: identifikasi berdasarkan kombinasi kolom kunci, hapus duplikat
📏
Inkonsistensi Format
Tanggal ditulis "01/07/2024" di satu baris dan "1 Juli 2024" di baris lain. Kota ditulis "Surabaya", "surabaya", "SBY", "sby". Satuan berbeda: "kg" vs "KG" vs "kilogram". Semua ini dianggap nilai berbeda oleh software.
→ Strategi: standardisasi case, format tanggal, dan satuan secara konsisten
🚀
Outlier & Nilai Tidak Masuk Akal
Suhu mesin tercatat 9999°C (error sensor), umur karyawan 150 tahun (kesalahan input), penjualan negatif (return tidak tercatat dengan benar), berat produk 0 kg. Bisa distorsi rata-rata dan model AI secara drastis.
→ Strategi: tetapkan batas logis, periksa dengan boxplot, koordinasi dengan pemilik data
🔤
Tipe Data Salah
Kolom angka disimpan sebagai teks karena ada satu sel berisi "N/A". Kolom tanggal diekspor sebagai angka serial Excel. Kolom kategori berisi angka 1/0 tapi seharusnya "Ya/Tidak". Software tidak bisa melakukan kalkulasi pada tipe yang salah.
→ Strategi: konversi eksplisit tipe data setelah membersihkan nilai bermasalah
🏗️
Struktur Data Tidak Rapi (Untidy Data)
Satu kolom berisi beberapa informasi ("Suhu: 85°C, Tekanan: 2bar"), nilai yang seharusnya jadi baris malah jadi kolom (Jan, Feb, Mar sebagai header), atau beberapa tabel yang harus digabung tidak memiliki kunci yang cocok.
→ Strategi: pisahkan kolom, reshape tabel (melt/pivot), standardisasi kunci join

Dataset di bawah adalah contoh ekspor nyata dari sistem pencatatan produksi manual. Identifikasi semua masalah yang Anda temukan sebelum melihat penjelasannya:

Masalah ditemukan
  • Duplikasi: PRD-001 muncul dua kali (baris 1 & 4)
  • Format tanggal: "01/07/2024" vs "1 Juli 2024"
  • Case inkonsisten: "M-02" vs "m-02" di kolom Mesin
  • Outlier sensor: Suhu 9999°C jelas error pembacaan
  • Missing value: Jumlah_Reject baris 2 berisi "—"
  • Nilai mencurigakan: Jumlah_Unit = 0 (mesin berhenti? tidak dicatat?)
  • Missing value: Kolom Operator kosong di baris 5
Data yang bersih terlihat
  • Satu format tanggal konsisten: YYYY-MM-DD
  • Kode mesin uppercase konsisten: M-01, M-02
  • Tidak ada duplikasi ID_Produksi
  • Nilai suhu dalam rentang logis: 60–110°C
  • Tidak ada sel kosong tanpa penjelasan
  • Jumlah_Unit selalu > 0 kecuali ada catatan alasan
  • Setiap baris punya nama operator yang valid

2. Data Cleaning Tanpa Coding

Untuk pertemuan ini kita menggunakan Microsoft Excel (atau Google Sheets) yang sudah familiar — bukan Python. Di dunia kerja nyata, banyak analisis awal tetap dilakukan di spreadsheet sebelum data masuk ke sistem AI. Memahami prosesnya secara manual membuat kamu lebih sadar saat mengotomasi proses yang sama dengan kode nanti.

📦

Dataset praktik hari ini: File data_produksi_mentah.xlsx tersedia di Google Classroom → Pertemuan 4. File berisi 3 sheet: Produksi (800 baris), Mesin (referensi), dan Operator (referensi). Buka file ini sekarang sambil mengikuti langkah di bawah.

Langkah Sistematis Data Cleaning

AUDIT
Langkah 0 — Audit Data Sebelum Menyentuh Apapun
Sebelum mengubah data, buat salinan sheet bernama "backup_original". Catat temuan awal: berapa baris total, berapa kolom, berapa sel kosong per kolom, tipe data tiap kolom. Ini dokumen jejak audit yang penting — kamu harus bisa menjelaskan setiap perubahan yang dilakukan.
Excel: Ctrl+End → lihat sel terakhir untuk cek ukuran dataset | Ctrl+A → COUNTA untuk cek isi
HAPUS
Langkah 1 — Hapus Duplikasi
Identifikasi baris yang benar-benar identik (semua kolom sama) dan baris yang memiliki ID sama tapi isi berbeda — keduanya perlu penanganan berbeda. Yang pertama bisa langsung dihapus; yang kedua perlu diperiksa mana yang benar.
Excel: Data → Remove Duplicates → pilih kolom kunci (ID_Produksi). Catat berapa duplikat ditemukan.
ISI
Langkah 2 — Tangani Missing Values
Tidak semua nilai kosong ditangani sama. Tiga strategi utama: (a) Hapus baris jika kolom kritis kosong dan tidak bisa diisi; (b) Isi dengan nilai statistik (rata-rata untuk numerik kontinu, modus untuk kategorikal); (c) Isi dengan nilai tetap seperti "Tidak Diketahui" untuk teks deskriptif. Pilih strategi berdasarkan kepentingan kolom dan proporsi data yang hilang.
Excel: Ctrl+H → Find: (kosong) → Replace: sesuai strategi | Gunakan AVERAGE/MEDIAN untuk menghitung nilai isian
FORMAT
Langkah 3 — Standardisasi Format & Konsistensi
Konversi semua tanggal ke format YYYY-MM-DD menggunakan kolom bantu dengan fungsi TEXT(). Standardisasi teks: ubah semua ke UPPER() atau PROPER() sesuai konteks. Trim spasi tidak terlihat dengan TRIM(). Pastikan kode mesin, nama kota, dan kategori mengikuti satu daftar referensi yang disepakati.
Excel: =TRIM(UPPER(A2)) untuk standarisasi teks | =TEXT(A2,"YYYY-MM-DD") untuk tanggal | Paste Special→Values setelah formula
OUTLIER
Langkah 4 — Identifikasi & Tangani Outlier
Gunakan conditional formatting untuk menyorot nilai di luar batas logis yang disepakati. Untuk kolom suhu mesin, batas logis mungkin 50–120°C — nilai di luar ini perlu di-flag. Penting: jangan langsung hapus outlier tanpa berkonsultasi dengan operator atau teknisi yang tahu konteks fisiknya. Tandai dulu dengan kolom "flag_outlier" = "Ya/Tidak".
Excel: Home → Conditional Formatting → Highlight Rules → Less Than / Greater Than dengan batas yang ditentukan domain expert
TIPE
Langkah 5 — Verifikasi Tipe Data
Pastikan kolom numerik tidak ada yang tersimpan sebagai teks (ditandai dengan alignment kiri di Excel). Pastikan kolom tanggal dikenali sebagai Date, bukan string. Kolom kategorikal yang akan digunakan sebagai filter di Power BI harus konsisten — tidak boleh ada variasi penulisan untuk nilai yang sama.
Excel: pilih kolom → lihat apakah nilai rata-rata/jumlah tampil di status bar — jika tidak muncul berarti tipenya bukan numerik
CATAT
Langkah 6 — Dokumentasikan Semua Perubahan
Buat sheet terpisah bernama "cleaning_log" yang mencatat: tanggal cleaning, kolom yang diubah, masalah yang ditemukan, metode yang digunakan, dan jumlah baris yang terpengaruh. Dokumentasi ini krusial agar analisis bisa direplikasi, diaudit, atau dijelaskan kepada manajemen jika ada pertanyaan tentang validitas data.
Format log: Kolom | Masalah | Jumlah terpengaruh | Tindakan | Tanggal | Nama
🎯

Aturan 80/20 data cleaning: Dalam proyek AI nyata, 80% waktu dihabiskan untuk memahami dan membersihkan data. Investasi waktu di tahap ini langsung menentukan apakah model yang dibangun di P-03 bisa dipercaya atau tidak. Tidak ada jalan pintas.

3. Visualisasi Data dengan Power BI / Looker Studio

Setelah data bersih, langkah berikutnya adalah memvisualisasikannya untuk menemukan pola yang tidak terlihat dari angka mentah. Visualisasi yang baik adalah jembatan antara data dan keputusan — ia menjawab pertanyaan bisnis spesifik, bukan sekadar menampilkan grafik cantik.

Prinsip: Mulai dari Pertanyaan Bisnis

❓

Pertanyaan yang harus dijawab dashboard ini:

  1. Mesin mana yang memiliki tingkat reject tertinggi dalam 30 hari terakhir?
  2. Apakah ada pola reject berdasarkan shift (pagi / siang / malam)?
  3. Bagaimana tren produksi harian — apakah ada penurunan yang perlu diinvestigasi?
  4. Apakah ada korelasi antara suhu mesin dan jumlah reject?

Jenis Visualisasi & Kapan Menggunakannya

Bar Chart
Perbandingan Antar Kategori
Bandingkan nilai antar kelompok diskrit — reject per mesin, output per shift, biaya per departemen. Urutkan dari tinggi ke rendah untuk memudahkan pembacaan.
Line Chart
Tren dari Waktu ke Waktu
Tampilkan perubahan nilai sepanjang periode — tren produksi harian, reject mingguan, konsumsi energi bulanan. Terbaik untuk mendeteksi kenaikan/penurunan gradual dan anomali.
Scatter Plot
Korelasi Dua Variabel
Apakah suhu mesin mempengaruhi jumlah reject? Apakah kecepatan produksi berkaitan dengan cacat? Scatter plot mengungkap hubungan linear, non-linear, atau tidak ada hubungan sama sekali.
Pie / Donut
Proporsi dari Keseluruhan
Komposisi reject berdasarkan jenis cacat, distribusi produksi antar lini. Hanya gunakan untuk maksimal 5 kategori — lebih dari itu sulit dibaca. Donut lebih modern dan mudah di-label.
Heatmap
Pola di Dua Dimensi
Reject rate per mesin per shift (matriks Mesin × Shift), korelasi antar semua variabel numerik. Warna secara intuitif menunjukkan intensitas — merah = masalah, hijau = baik.
Box Plot
Distribusi & Outlier
Tampilkan median, IQR, dan outlier sekaligus. Sangat berguna untuk membandingkan distribusi suhu, waktu siklus, atau jumlah defect antar mesin atau operator dalam satu tampilan.

Panduan Membangun Dashboard di Power BI

Pastikan Power BI Desktop sudah terinstal (link di Google Classroom). Buka Power BI → pilih "Get Data" → Excel → arahkan ke file data_produksi_bersih.xlsx yang sudah kamu bersihkan tadi.

1
Load & Periksa Data di Power Query
Saat data dimuat, Power BI otomatis membuka Power Query Editor. Periksa tipe data setiap kolom — pastikan kolom tanggal bertipe Date, numerik bertipe Decimal/Integer, dan kategori bertipe Text.
Home → Transform Data → lihat panel "Data Type" di ribbon
2
Buat Kolom Kalkulasi Baru (DAX Sederhana)
Tambahkan kolom Reject Rate = Jumlah_Reject / Jumlah_Unit × 100. Ini adalah KPI utama yang akan ditampilkan di semua visualisasi. Di Power BI, klik kanan tabel → Add Column → masukkan formula DAX.
DAX: Reject_Rate = [Jumlah_Reject] / [Jumlah_Unit] * 100
3
Bangun 4 Visual Utama
Seret visual dari panel kanan ke kanvas:
  • Bar Chart → Axis: Mesin, Values: Reject_Rate (rata-rata) → jawab: mesin mana paling bermasalah?
  • Line Chart → Axis: Tanggal, Values: Jumlah_Unit → jawab: bagaimana tren produksi?
  • Stacked Bar / Matrix → Rows: Mesin, Columns: Shift, Values: Reject_Rate → jawab: pola reject per shift?
  • Scatter Plot → X: Suhu_Mesin, Y: Reject_Rate → jawab: apakah suhu berpengaruh?
4
Tambahkan Slicer (Filter Interaktif)
Tambahkan Slicer untuk kolom Mesin, Shift, dan Tanggal. Dengan slicer, pengguna dashboard bisa memfilter semua visual sekaligus hanya dengan satu klik — tanpa perlu membuat halaman terpisah untuk setiap mesin.
Visualizations → Slicer → drag field ke Field box → format Style: Dropdown atau List
5
Tambahkan Card KPI di Bagian Atas
Card visual menampilkan satu angka besar — cocok untuk KPI eksekutif. Tambahkan 4 card: Total Produksi, Total Reject, Reject Rate Keseluruhan, dan Jumlah Hari Data. Letakkan di baris paling atas dashboard.
Visualizations → Card → drag measure ke Fields. Format angka di Format pane
6
Format & Beri Judul yang Deskriptif
Setiap visual harus punya judul yang menjawab pertanyaan, bukan sekadar nama kolom. Bukan "Jumlah_Reject by Mesin" — tapi "Mesin Mana yang Paling Banyak Menghasilkan Reject?". Tambahkan catatan sumber data dan tanggal pembaruan di sudut dashboard.

4. Pola yang Dicari Saat EDA

Exploratory Data Analysis bukan sekadar membuat grafik — ini adalah proses investigasi yang dipandu pertanyaan. Berikut adalah pola-pola yang paling sering ditemukan di data industri dan harus diperhatikan:

Pola yang Ditemukan Cara Mendeteksi Implikasi Operasional Tindak Lanjut
Reject spike pada shift malam Bar chart Reject Rate per Shift Kemungkinan kelelahan operator, pencahayaan kurang, atau pengawasan lebih sedikit Audit SOP shift malam, evaluasi rotasi pekerja, tambah inspeksi
Penurunan output gradual satu mesin Line chart per mesin selama 30 hari Kemungkinan komponen aus, perlu maintenance preventif Jadwalkan inspeksi sebelum breakdown total (predictive maintenance)
Korelasi positif suhu–reject Scatter plot Suhu vs Reject Rate Mesin overheat mempengaruhi kualitas produk — ada batas suhu kritis Tetapkan alarm suhu otomatis, periksa sistem pendinginan
Outlier reject rate satu hari Box plot atau line chart harian Kejadian luar biasa: bahan baku bermasalah, kerusakan mendadak, atau error pencatatan Investigasi log produksi hari tersebut sebelum menyimpulkan
Pola siklus mingguan/bulanan Line chart dengan granularitas hari-dalam-minggu Senin pagi sering bermasalah (mesin baru pemanasan), Jumat output turun Sesuaikan jadwal warm-up, pertimbangkan buffer produksi di awal minggu
🔍

Bedakan korelasi dan kausalitas: EDA menemukan korelasi — "suhu tinggi berbarengan dengan reject tinggi". Ini belum berarti suhu menyebabkan reject. Mungkin ada faktor ketiga (misalnya: bahan baku yang sama yang masuk saat itu memang berkualitas buruk). Gunakan temuan EDA sebagai hipotesis untuk diinvestigasi, bukan kesimpulan final.

Ringkasan Pertemuan Ini

  • Data industri dari MES, ERP, dan form manual hampir selalu kotor — jenis masalah umum: missing values, duplikasi, inkonsistensi format, outlier, dan tipe data salah
  • Data cleaning tanpa coding bisa dilakukan di Excel secara sistematis: audit → hapus duplikat → tangani missing → standardisasi format → flag outlier → dokumentasikan
  • Prinsip "Garbage In, Garbage Out" berlaku mutlak — model AI sebaik data yang menjadi inputnya
  • Setiap visualisasi harus menjawab pertanyaan bisnis spesifik, bukan sekadar menampilkan data
  • Pilihan chart bergantung pada jenis pertanyaan: perbandingan → bar, tren → line, korelasi → scatter, proporsi → pie/donut, distribusi → box plot
  • EDA menghasilkan hipotesis, bukan kesimpulan — korelasi yang ditemukan perlu diverifikasi dengan investigasi domain

  4. Opsional (bonus): Coba Looker Studio (Google Data Studio) sebagai alternatif Power BI. Hubungkan data dari Google Sheets dan buat visualisasi yang sama. Bandingkan kemudahan penggunaannya dalam 150 kata.
